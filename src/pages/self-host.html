Clone it, run it, pay nothing.

fein is Apache 2.0 licensed and self-hosted by design. There is no trial, no seat count, and no paid tier. This page is an honest account of the setup.

View on GitHub Read the setup

A machine, an LLM key, and someone comfortable in a terminal.

The default stack runs entirely on local disk, so there is nothing external to provision.

Somewhere to run it

A server you control. The default stack is SQLite, LanceDB, and Ladybug on local disk. When you outgrow that, Postgres, Neo4j, pgvector, Chroma, Qdrant, Weaviate, and Milvus are swappable through the environment file.

An LLM API key

Adding a document runs entity extraction and embedding, so ingestion and search need a key; browsing works without one. The default is openai/gpt-5-mini, and Anthropic, Gemini, Ollama, Azure, Bedrock, and any OpenAI-compatible endpoint work too.

Admin access to each source

Every system you want read has its own OAuth app or API credential to register. This part takes the most calendar time.

Getting it running.

Three short steps, then one long one.

  1. Clone the repository

    Everything is in one repo, including the connectors and the dashboard.

    git clone https://github.com/clippycommits/fein cd fein
  2. Add a model key

    Copy the template and set your key; it documents every provider and every swappable database.

    cp .env.template .env # then set LLM_API_KEY="sk-..." in .env
  3. Start the stack

    One command. It sets up the Python environment and UI dependencies if they are missing, starts the API on port 8000 and the dashboard on port 3000, and opens a browser once both answer. Logs land in .run/api.log and .run/ui.log.

    ./fein # start the stack ./fein stop # stop it ./fein status # what is running
  4. Connect your sources, then backfill

    Register an OAuth app for each system, connect it in the dashboard, and let fein read your history back. This is where the weeks go; see below.

One thing to get right before anyone else uses it. The local stack runs single-user with authentication off, which is fine on your laptop and wrong for anything shared. Set ENABLE_BACKEND_ACCESS_CONTROL=True and put real per-user isolation in place before you point a team at it.

The install is an afternoon. The rest is not.

Making fein useful means pointing it at a decade of real mail. We would rather say so here than have you find out in week three.

Where the time actually goes.

  • →OAuth apps, one per source. Each of Gmail, Calendar, Drive, LinkedIn, and your CRM needs its own registered application and admin consent. Google and Microsoft both review some scopes. Budget days rather than hours; most of it is waiting on other people.
  • →The historical backfill. Reading years of mail and documents is slow, rate-limited by the upstream APIs, and needs restarting when it breaks. It is the single longest step.
  • →Entity resolution. In a decade of mail, one person often looks like four: work address, personal address, a maiden name, a typo. Getting to one record per human is what makes the graph answer well.
  • →Keeping it alive. Upstream APIs change on their own schedule. Once fein is load-bearing, somebody at the firm owns 30 integrations for as long as you run it.
That list is a quarter of someone’s time.

This work is why the managed option exists. Same software, same servers, same licence: an engineer of ours does the four things above and hands it over working on day 14. If you would rather do it yourself, everything you need is public.

What self-hosters ask.

Is this a crippled version of the paid product?

No. There is one codebase and one binary, with no feature flags. The firms paying us run exactly what you clone; they buy setup and upkeep.

What is the licence, exactly?

Apache 2.0. fein derives from topoteretes/cognee and keeps its licence, the upstream attribution, and a statement of changes. You can run it commercially, modify it, and keep your changes private. Over a shorter licence, the one obligation Apache adds is attribution: keep the NOTICE file with the code.

Do you see anything we run?

Nothing. There is no telemetry, no analytics, and no control plane. We do not know you are running it unless you tell us, which also means we cannot help unprompted when something breaks.

Can we get support?

Through GitHub issues, alongside everyone else, at whatever pace we get to them. Guaranteed response times and a named engineer come with the managed plan.

Can we start here and move to managed later?

Yes. We pick up whatever you have built rather than starting again. The build fee is the same either way.
